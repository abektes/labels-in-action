# Fun Names + BYOK Cloud Naming Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the camera name objects through the user's own OpenRouter key, with an optional "fun names" mode that adds affectionate nicknames, while keeping the key out of the WebView.

**Architecture:** Pure TypeScript core (`cloud-naming-core.ts`: request building, reply parsing, error wording, namer choice) is unit-tested with vitest. An app-local Android plugin (`CloudNaming`) owns the key (Keystore AES-GCM) and makes the HTTP call. A thin bridge (`cloud-naming.ts`) downsizes the frame and exposes a `SuggestionProvider`. The UI adds an "AI naming" modal, and the live overlay and scan tray gain fun chips.

**Tech Stack:** Svelte 5, TypeScript, Capacitor 8, Java (Android Keystore, HttpURLConnection), vitest.

Spec: `docs/superpowers/specs/2026-09-23-fun-names-design.md`

## Global Constraints

- The key is never baked into the build, never stored in localStorage, never returned to JS (only `configured` + `hint`).
- Native HTTP only to `https://openrouter.ai/api/v1/chat/completions` and `https://openrouter.ai/api/v1/key` (hard-coded).
- Default model `z-ai/glm-5.3-flash`; preset alternative `deepseek/deepseek-v4.1-flash`.
- Fun names ≤ 22 chars; plain names ≤ 3 words (reuse existing `parseLabelOptions` limits).
- Request: `temperature` 1.0 fun / 0.3 plain, `max_tokens` 300, `reasoning: {enabled: false}`, image ≤ 768 px long edge, JPEG 0.8.
- Nano stays plain-only. Fun requires a key.
- Android only for cloud naming; web/PWA shows nothing new.

**Interfaces (Produces, JS-visible):**
```ts
setKey({ key: string }): Promise<{ configured: true; hint: string }>
clearKey(): Promise<void>
keyStatus(): Promise<{ configured: boolean; hint?: string }>
checkKey(): Promise<{ status: number; body: string }>          // GET /api/v1/key
complete({ body: string }): Promise<{ status: number; body: string }>  // POST chat/completions
```
Non-2xx responses resolve (status + body), network faults reject; JS maps both via `describeCloudError`. Calls run on a background executor; 30 s connect+read timeout. `setKey` trims and rejects empty/whitespace/over-500-char values. Hint = `sk-or-…` + last 4.
